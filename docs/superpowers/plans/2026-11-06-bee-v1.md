# bee v1 Implementation Plan

> **For agentic workers:** execute task by task under `worktree-dispatch`, one fresh worker per task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One live board, held by every attached browser, Claude session and an always-on host, that agents redraw as A2UI surfaces. The brainstorming visual companion runs on it.

**Architecture:** Every peer holds a kuilt replica of one `BoardState` lattice. Browsers hold theirs in wasm, behind the stock A2UI Lit renderer. Claude sessions hold theirs in a JVM MCP bridge. Everyone reaches the JVM host over outbound WebSockets. The host relays the board at `/ws/board` and keeps it on disk. It is also the single Raft voter that commits claims at `/ws/claims`, and it alone writes the claim mirror onto the board.

**Tech Stack:** Kotlin Multiplatform (JVM + wasmJs), Gradle 9.4.1, JDK 25, kuilt `0.7.0-dev.1690` (`kuilt-crdt`, `kuilt-quilter`, `kuilt-websocket`, `kuilt-gossip`, `kuilt-cluster`, `kuilt-raft`, `kuilt-liveness`, `kuilt-store`, `kuilt-test`), Ktor 3.5.2, A2UI (`@a2ui/lit` + `@a2ui/web_core`, exact versions pinned by Task 1), MCP Kotlin SDK `io.modelcontextprotocol:kotlin-sdk-server:0.16.0`, Playwright.

**Spec:** [`docs/superpowers/specs/2026-11-06-bee-design.md`](../specs/2026-11-06-bee-design.md) (tractat-us/bee#1). It carries this plan's amendments, decisions and LAN pairing ruling, so executors read the spec for the design and this plan for the tasks.

- **Test gates:**
  - The required gate is deterministic: an in-memory loom and virtual time (`kuilt-test`, `QuilterConfig(expectVirtualTime = true)`).

- **Renderer:** A2UI protocol v0.9.1 (`version: "v0.9"`) from the `v0_9` entry points, unless Task 1 finds that both packages implement v1.0 (A9). The renderer is stock and never sees a CRDT, and merge rules live only in the replica.
- **Transport:** everyone talks through the host over WebSockets, outbound only. No WebRTC.
- **`Sketch`:** content runs only in `<iframe sandbox="allow-scripts">`, never `allow-same-origin`, with no network beyond the page. Nothing executes surface content outside that sandbox.
- **Claims and records:**
  - Nothing reassigns itself. An orphaned claim stays held and flagged until a participant decides.
  - Records are addressed to a surface, never to a session instance. Handling a record goes through a claim.
  - The v1 voter set is the host alone. The host votes and never claims.
- **Board content:**
  - "Clear the board" closes surfaces and never deletes them.
  - Bridge tools make "this goes on the shared board" an explicit act, never a side effect.
- **Surface design (A1, A12):**
  - Content a basis must name, or a handler must reason about having seen, is an appended, never-edited `Rga` entry: poll options and question revisions as `JsonNode.Array` elements in a surface, and action records in the board's own `BoardState.records`. Correcting one means removing it and appending a new entry with a new identity.
  - Editable state lives in an object keyed by a stable id, with its order kept separately, and no basis names it: cards, columns, components, data fields.
  - **Leaf writes start from the register just read** (`leaf.register.set(replica, v)`), never `MVRegister.empty().set(…)` (A13).
- **Conventions:**
  - Test names have no `test` prefix. Multi-assert tests use `us.tractat.kuilt.test.assertAll`.
  - One PR per task. Never use the word "chore" in commits or PR titles. Never commit `next-plan.md` or `morning-report*.md`.

## Review Focus

1. **Malformed agent-supplied A2UI** (no `root`, a child id naming no component, a type outside the Notions catalog). The bridge refuses with an error that names the id or type, and the board is unchanged. A browser shown an invalid surface anyway renders a placeholder, not the renderer. Tests: Task 2 `SurfaceValidatorTest`, Task 7 `BeeToolsTest.openRefusesMalformedComponents`.
2. **Markup in non-`Sketch` text** (`<img onerror=…>` in a title, label or option) is shown as literal text. Test: Task 11, `notions.spec.mjs` › `markup in labels renders as text`.
3. **A wait that ends badly.** The client's tool timeout or `/clear` cancels `bee_wait_action` after it claimed a record but before it returned it. No claim is left held by a wait nobody is in. Test: Task 7, `BridgeClaimsTest.cancelledWaitReleasesItsClaim`.
4. **The host is down when someone acts.** The edit lands locally, the page says it's offline, and the edit syncs on return. A claim returns `Unavailable`, never `Won`. If that claim commits later, the client releases it. Test: Task 6, `ClaimsClientTest.lateCommitOfTimedOutClaimIsReleased`.
5. **An oversized payload.** A `Sketch` above the seam's `maxPayloadBytes` is refused with a message that states the limit, and the board keeps working. Test: Task 8, `SketchSurfaceTest.oversizedSketchIsRefusedWithItsLimit`.

## Decisions this plan makes (spec §10)

- **MCP tools:**
  - Board: `bee_board`, `bee_surface_open`, `bee_surface_update`, `bee_surface_close`, `bee_board_clear`.
  - Records: `bee_wait_action`, `bee_list_actions`, `bee_action_done`.
  - Claims and presence: `bee_claim`, `bee_release`, `bee_presence`.

  Every writing tool's description starts "Puts … on the shared board, visible to everyone attached".
- **Which records a session handles:** subscription by surface. Waiting on a surface is how a session handles it, and any session may wait on any surface.
- **Quiet timeout:** 20 minutes since the bridge's last tool call. **Crash:** a board link lost for the 30 s heartbeat reconnect window.
- **Layout:** open surfaces stack in `openedAt` order (ties by id). Closed surfaces sit in a collapsed history strip, newest first, and reopen with their records.
- **The A2UI mapping** (`bee-a2ui`) depends only on `kuilt-crdt`, so it can graduate. Revisit after Task 4.
- **Peer identity:** agents are `agent:<name>#<8 hex>`, fresh per bridge identity. `name` is `$BEE_SESSION_NAME`, else the working directory's basename. Humans are `human:<name>` across tabs and devices. Only agents depart.
- **CRDT authors are not peer identities.** They're `web-<uuid>` per page load, `mcp-<uuid>` per bridge process, and `host-<uuid>` per host boot.
- **Host:** port `8233` ("BEE" on a keypad), data dir `~/.bee/host/`, routes `/`, `/ws/board`, `/ws/claims`. Loopback only until Task 10. The host has no write route; test fixtures write through a JVM `BoardClient`.
- **Notions catalog id:** `https://tractat.us/bee/catalogs/notions/v1.json`. It holds the basic catalog's components plus `Sketch`, `Board` and `Poll`.
- **Projection winner:** the greatest value under a total order on `JsonValue`: `Null` < `Bool` < `Num` < `Str`, then by value, with strings compared by UTF-16 code unit. That's peer-stable, never arrival order. The full set is published at `/_bee/conflicts/<escaped pointer>`.

## kuilt tracking-issue items

These are the gaps known now. Each goes on the kuilt tracking issue (§11), not into bee:

- **Learner membership grows without bound.** Learners are never removed from membership (`ServerCluster.kt:185-209`, `CoreLearnerAdmission.kt:106`), so per-tab and per-`/clear` identities grow the configuration forever.
- **The documented leaf write is a footgun.** `Leaf(MVRegister.empty().set(…))` creates phantom conflicts. `CrdtSamples.kt:318-340` and Writerside `crdt-mvregister.md` teach it. A `JsonCrdt.setValue(key, JsonValue)` was proposed.
- **The docs misdescribe `Rga`.** Its elements are write-once, but Writerside `crdt-jsoncrdt.md` says otherwise.
- **`Quilted.delivered(dot)`**, which #2869 CONTRACTS confirmed, with bee as the second consumer.
- **A published hub-spoke client loom.** `RelaySpokeLoom` is demo-only.
- **`QuiltedPersistence`**, the `Quilter`↔`DurableStore` adapter (Task 9), as a graduation candidate.
- **Unauthenticated learner identity.** A learner's identity comes from an unauthenticated query parameter. Task 10's pairing key gates it on the LAN, and on loopback it stays trusted.

## Spec gap for Iain

The spec now carries this ruling, in [§5.7](../specs/2026-11-06-bee-design.md#57-letting-a-second-screen-in-iain).

- **Access control on the LAN: ruled (Iain, 2026-11-06). A key, with Bluetooth-style pairing.** A browser that arrives over the LAN without a key shows a six-digit code, and the board asks the current participants to type it in. A matching code admits the browser and gives it a key. Task 10 carries the design. Tasks 1–9 bind loopback only.
  - **Design calls:** the host binds loopback unless `--lan` is passed, and loopback connections need no key. A URL key (`?k=`) still admits, for a join link or QR code. A code expires after 2 minutes, and 3 wrong entries void it. **Only human peers may admit a device.** This departs from the orphan-decision rule on purpose: admission is access control, and a typed code proves someone can see the new screen. Iain confirmed: humans only, for now.
  - **Limits:** this is an access gate, not transport security. It runs over plain HTTP, and peer kind is self-declared by trusted local peers. The spec's §9 sharing rule still governs what goes on the board.

### Task 10: A second screen (spike 7)

**Iain's ruling (see "Spec gap for Iain"): a key, with Bluetooth-style passkey pairing.** Only human peers admit a device. A device with no key gets no board state, no presence and no claims until a human admits it.

**Flow.**
1. A browser loads the page from a non-loopback address with no key. It opens `/ws/pair`, an endpoint that carries no board or claims traffic. The host mints a 6-digit code and a pairing id and sends both to that browser only. The browser shows the code full screen ("Enter this code on the board to join").
2. The host writes a join-request surface onto the board: "A device wants to join: enter the code it shows". The code itself is never written to the board. The surface holds the pairing id, the device's address and its `?screen=` name if it gave one.
3. A participant types the code into that surface. The input arrives as an action record (§6.2). The host checks four things: the actor is a human peer (A7), the code matches, the pairing hasn't expired (2 minutes), and fewer than 3 wrong entries have been made. On a match it mints a key, sends it down `/ws/pair`, and closes the request surface with "admitted by <name>". A wrong entry updates the attempt count, and a third voids the pairing. An agent's entry is refused and noted on the surface.
4. The browser stores the key in `sessionStorage` and dials `/ws/board` and `/ws/claims` with it. With `--lan` on, both endpoints refuse a non-loopback connection that has no valid key, and so does `?k=` with a wrong key. Keys live in host memory, so a host restart re-pairs every LAN device.
