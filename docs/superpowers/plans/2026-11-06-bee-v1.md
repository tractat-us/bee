# bee v1 Implementation Plan

> **For agentic workers:** execute task by task under `worktree-dispatch`, one fresh worker per task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One live board, held by every attached browser, Claude session and an always-on host, that agents redraw as A2UI surfaces. The brainstorming visual companion runs on it.

**Architecture:** Every peer holds a kuilt replica of one `BoardState` lattice. Browsers hold theirs in wasm, behind the stock A2UI Lit renderer. Claude sessions hold theirs in a JVM MCP bridge. Everyone reaches the JVM host over outbound WebSockets. The host relays the board at `/ws/board` and keeps it on disk. It is also the single Raft voter that commits claims at `/ws/claims`, and it alone writes the claim mirror onto the board.

**Tech Stack:** Kotlin Multiplatform (JVM + wasmJs), Gradle 9.4.1, JDK 25, kuilt (`kuilt-crdt`, `kuilt-quilter`, `kuilt-websocket`, `kuilt-gossip`, `kuilt-cluster`, `kuilt-raft`, `kuilt-liveness`, `kuilt-store`, `kuilt-test`), Ktor 3.5.2, A2UI (`@a2ui/lit` + `@a2ui/web_core`, exact versions pinned by Task 1), MCP Kotlin SDK `io.modelcontextprotocol:kotlin-sdk-server:0.16.0`, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-06-bee-design.md` (tractat-us/bee#1), as amended by the **Spec amendments** section below. Executors read both. Where they disagree, the amendment wins.

## Global Constraints

- Every shell command below runs after `source ~/.sdkman/bin/sdkman-init.sh && sdk use java 25.0.2-tem`.
- The A2UI protocol is v0.9.1 (message `version: "v0.9"`), imported from the `v0_9` entry points, unless Task 1 finds the packages implement v1.0 (Amendment A9). The renderer is stock and never sees a CRDT. Merge rules live only in the replica.
- Consume kuilt by coordinates. Use Tigris `s3://maven/` (the `TigrisKuilt` block in `fireworks-compose/settings.gradle.kts`, with `S3_BUILD_CACHE_*` credentials) and `kuilt-bom` `0.7.0-dev.1641` or newer, one version for every module. Composite build: `if (file("../kuilt").exists()) includeBuild("../kuilt")`.
- **Never fork, vendor or monkey-patch kuilt.** A gap becomes a `tractat-us/kuilt` issue (search first). A bee workaround sits behind a comment naming that issue. Report every issue you file.
- Everyone talks through the host over WebSockets, outbound only. No WebRTC.
- `Sketch` content runs only in `<iframe sandbox="allow-scripts">`, never `allow-same-origin`, with no network beyond the page. Nothing executes surface content outside that sandbox.
- Nothing reassigns itself. An orphaned claim stays held and flagged until a participant decides.
- Records are addressed to a surface, never to a session instance. Handling a record goes through a claim.
- The v1 voter set is the host alone. The host votes and never claims.
- "Clear the board" closes surfaces and never deletes them.
- Bridge tools make "this goes on the shared board" an explicit act, never a side effect.
- **Surface design (A1):** anything a basis must name, or a handler must reason about having been seen, is an appended `Rga` entry (a `JsonNode.Array` element), never an edited leaf. That covers records, poll options, question revisions and cards.
- Test names have no `test` prefix. Multi-assert tests use `us.tractat.kuilt.test.assertAll`.
- One PR per task. Never use the word "chore" in commits or PR titles. Never commit `next-plan.md` or `morning-report*.md`.

## Review Focus

1. **Malformed agent-supplied A2UI** (no `root`, a child id naming no component, a type outside the Notions catalog). The bridge refuses with an error that names the id or type, and the board is unchanged. A browser shown an invalid surface anyway renders a placeholder, not the renderer. Tests: Task 2 `SurfaceValidatorTest`, Task 5 `BeeToolsTest.openRefusesMalformedComponents`.
2. **Markup in non-`Sketch` text** (`<img onerror=…>` in a title, label or option) is shown as literal text. Test: Task 9, `notions.spec.mjs` › `markup in labels renders as text`.
3. **A wait that ends badly.** The client's tool timeout or `/clear` cancels `bee_wait_action` after it claimed a record but before it returned it. No claim is left held by a wait nobody is in. Test: Task 5, `BridgeClaimsTest.cancelledWaitReleasesItsClaim`.
4. **The host is down when someone acts.** The edit lands locally, the page says it's offline, and the edit syncs on return. A claim returns `Unavailable`, never `Won`. If that claim commits later, the client releases it. Test: Task 4, `ClaimsClientTest.lateCommitOfTimedOutClaimIsReleased`.
5. **An oversized payload.** A `Sketch` above the seam's `maxPayloadBytes` is refused with a message that states the limit, and the board keeps working. Test: Task 6, `SketchSurfaceTest.oversizedSketchIsRefusedWithItsLimit`.

## Spec amendments

Two reviews of the spec (one spot-checked against kuilt `280de6b49`) and a prior-art pass landed after it merged. A follow-up spec PR carries these amendments, and this plan is built on them.

- **A1 (§6.2) Anything a basis must name is an appended `Rga` entry, never an edited leaf.** This follows #2869's own rule ("a scalar input has no identity"; its prototype appended a `PreferenceSet` entry rather than use a register). `MVRegister` dots stay private, by Iain's ruling, so bee makes no kuilt ask to open them. The rule constrains the Notions catalog and surface design. Action records, poll options, question revisions and cards are all appended entries in a `JsonNode.Array`, whose `Rga` dots `JsonCrdt.causalDots()` aggregates. A scalar leaf is display state that no handler may reason about.
- **A2 (§6.3) Claims are a state machine, and the host owns the mirror.** `ClientSessionTable` dedups one client's retries, not two peers racing. In `ClaimTable`, the first committed `Claim` of a free target wins, and later ones apply as rejected. The host applies the committed log and is the only writer of `BoardState.claims` and `departed`. A held claim carries a **fencing token**, the `(term, index)` of the entry that granted it. A `Complete` or `Release` with a stale token applies as rejected.
- **A3 (§6.4) "Dead" is a committed retirement.** A crashed or quiet session is retired when the host commits `Depart(identity, reason)`. The state machine rejects every later command from a retired identity. A bridge that finds itself retired re-identifies through the `/clear` path, and refuses board writes, before it acts again.
- **A4 (§5.1, §5.4) Two endpoints, one identity rule each.** The board runs reconnect shape (A) at `/ws/board`: `KtorMeshClientLoom` spokes into `hostedOverlay`, with a fresh fabric `PeerId` per weave and a `Quilter` rebuilt per connection from the held state. Claims run `clusterClient` over `KtorClientLoom` into `serverCluster`'s `KtorRoomHost` at `/ws/claims`, with a stable `PeerId` within a join and a fresh join on every tear. Neither endpoint resumes a room, so neither depends on the reconnect window. The reviewed alternative puts both on one `KtorRoomHost`, with the board `Quilter` on a second room channel. It's Task 4's fallback if the two-endpoint shape fails there.
- **A5 (§5.4, §12.6) kuilt ships the stores. Only the Quilter adapter is missing.** `kuilt-store` provides `FileChannelDurableStore` (JVM) and `IndexedDbDurableStore` (wasmJs), and `kuilt-raft` provides `DurableStoreRaftStorage`. For Raft, durability is configuration: pass `DurableStoreRaftStorage` as `serverCluster`'s `storageFactory`, since it defaults to `InMemoryRaftStorage`. The one gap is a `Quilter`↔`DurableStore` persistence adapter: snapshot on change, seed `initial` on start, restore a stable replica id. That piece is generic. bee proves it behind a seam with no bee types (Task 7), and it's a candidate for the kuilt tracking issue (§11), never a local patch to kuilt. A host restart under claims is proven in the claims spike (Task 4).
- **A6 (§12) Spike order.** Spike 3 needs claims, because handling goes through a claim. So spike 3 splits. Its risky half (bridge lifecycle, the `/clear` channel, tool-call hold limits) runs beside spikes 2 and 4. Its board-and-claims half joins them afterwards (Task 5).
- **A7 (§5.1) Browser identity.**
  - The human name is asked once and kept in `localStorage["bee.human.name"]`.
  - Every tab is its own replica, with a fresh CRDT author per page load.
  - One tab at a time writes the IndexedDB snapshot: the one holding the Web Lock `bee-board-store`.
  - A room screen is a named human peer opened with `?screen=<name>`, and it never proposes a claim.
- **A8 (§5.2) The `/clear` channel.** At start, the bridge writes `~/.bee/run/<claudePid>.json` (`{"port":N}`) and serves `POST /retire` on loopback. `claudePid` is the nearest ancestor process named `claude`. The `SessionStart` hook finds the same pid by the same rule and POSTs to it.
- **A9 (§5.3) The A2UI pin is a spec version.** Task 1 pins exact `@a2ui/lit` and `@a2ui/web_core` versions and records which spec version they implement. It prefers v1.0 if the packages implement it and falls back to v0.9.1. On 2026-11-06, `@a2ui/lit@0.15.0`, the latest, exports only `0.8` and `v0_9`.
- **A10 (§5.2) Waits are bounded.** `bee_wait_action` returns within 45 s, or a caller-chosen value up to 60 s. It returns `{record?, timedOut, cursor}` and sends progress notifications while it holds. `bee_list_actions(since)` reads without blocking. Task 3 measures how long the installed Claude Code really holds a call.
- **A11 (§5.6) Writers validate, not the host.** The host can't refuse a CRDT write. So the bridge validates a surface against the Notions schema before writing it, and the browser driver validates before rendering, showing a placeholder for an invalid surface.

## Decisions this plan makes (spec §10)

- **MCP tools:**
  - Board: `bee_board`, `bee_surface_open`, `bee_surface_update`, `bee_surface_close`, `bee_board_clear`.
  - Records: `bee_wait_action`, `bee_list_actions`, `bee_action_done`.
  - Claims and presence: `bee_claim`, `bee_release`, `bee_presence`.

  Every writing tool's description starts "Puts … on the shared board, visible to everyone attached".
- **Which records a session handles:** subscription by surface. Waiting on a surface is how a session handles it. Any session may wait on any surface.
- **Quiet timeout:** 20 minutes since the bridge's last tool call. **Crash:** a board link lost for the 30 s heartbeat reconnect window.
- **Layout:** open surfaces stack in `openedAt` order (ties by id). Closed surfaces sit in a collapsed history strip, newest first, and reopen with their records.
- **The A2UI mapping** (`bee-a2ui`) depends only on `kuilt-crdt`, so it can graduate. Revisit after Task 2.
- **Peer identity:** agents are `agent:<name>#<8 hex>`, fresh per bridge identity. `name` is `$BEE_SESSION_NAME`, else the basename of the working directory. Humans are `human:<name>` across tabs and devices. Departures apply to agents only.
- **CRDT authors are not peer identities.** They're `web-<uuid>` per page load, `mcp-<uuid>` per bridge process, and `host-<uuid>` per host boot.
- **Host:** port `8233` ("BEE" on a keypad), data dir `~/.bee/host/`, routes `/`, `/ws/board`, `/ws/claims`. It binds loopback until Task 8.
- **Notions catalog id:** `https://tractat.us/bee/catalogs/notions/v1.json`. It holds the basic catalog's components plus `Sketch`, `Board` and `Poll`.
- **Projection winner:** `MVRegister`'s dots are private, so the projection can't use "highest dot". It uses the value with the greatest canonical JSON encoding, compared lexicographically. That's peer-stable, never arrival order. The full set is published at `/_bee/conflicts/<escaped pointer>`, and the next write that has seen every value collapses it.

## kuilt#2869 checkpoint (after the plan)

Inputs: kuilt `demo/workspace/CONTRACTS.md` at `53f89b34`, and `kuilt-workspace/docs/spikes/2026-10-reconnect-shape.md`.

**What bee picks up**

- **The input-history contract.** A record is an immutable `Rga` element whose identity is its dot, so a correction is a new record. Its basis is read once, from the actor's own replica, as it acts. Capturing at the right moment is the code's obligation, so Task 2 pins it with a test that reds on late capture.
- **"A scalar input has no identity"**, adopted as #2869 ruled it (A1). Every input a basis names is an appended `Rga` entry, never a register. bee makes no ask to expose leaf dots.
- **The two-armed delivery rule** (`causalDots()` ∪ `causalFloor()`) is written once, in `Basis.saw`. bee is the second consumer #2869 said `Quilted.delivered(dot)` was waiting for, so Task 2 files that issue. None exists yet.
- **"Unknown, never applicable."** A handler whose replica lacks a dot the basis names gets `basisComplete = false`.
- **Reconnect shape (A)** (A4), with both of its easy-to-miss details: the identity-guarded mirror, and each spoke's `GossipSeam` started on the connection's child scope.
- **Not in v1:** the re-check of a shown answer (kuilt#2880). bee keeps the basis it would need.

**What #2869 could pick up from bee**

- **A target beyond the JVM.** Capture in wasm in the browser (Tasks 1–2), which CONTRACTS doesn't establish.
- **A second capture consumer.** If `Basis.capture` matches `InputCapture.capture`, that's evidence for naming the API in kuilt.
- **The "Authority" pile.** Exactly-once claims with fencing tokens through `kuilt-cluster`, a voter that never claims, and orphaned work decided by any participant (Tasks 4, 5, 9).
- **M5's question**, answered for a board with no fixed screen, including the projection rule.

    - Any other `Claim` applies as rejected.

    - `Reassign` applies only to an `Orphaned` target and mints a new token.

  - **`Poll`**: `question` (a data path to an array of revisions; the last one shows, and revising appends), `options` (a data path to a `JsonNode.Array`, so each option has a dot, A1), and `answers` (a data path to an object keyed by `PeerIdentity.toString()`). Answering writes `answers[<me>]` and appends a record, so one person counts once.
  - **`Board`**: `columns` (`[{id, title, owner?}]`) and `cards` (an array of `{id, label, column}`). A drop writes `column` and appends a `drop` record.
  - `OrphanDecisions`: for each `Orphaned` target, the host opens `orphan-<target>`, a `Poll` with options "Reassign to <each present peer>", "Release" and "Wait". The answerer's own client proposes `Reassign` or `Release`. "Wait" proposes nothing, and screen peers can't answer. The host closes the surface once the target isn't `Orphaned`, and itself proposes only `Depart`.
  - `HistoryStrip`: closed surfaces, newest first, collapsed. A click runs `reopenSurface`.
